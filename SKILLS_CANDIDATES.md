# Навыки и субагенты

## Доступные процедуры

| Источник | Когда подходит |
| --- | --- |
| Каталог навыков текущей сессии | `use-mcp-tools` применим при сверке изменяемых API и проверке живого веб-стенда через Context7 или Playwright. Для текущей инвентаризации использованы официальные источники и локальные системные команды. |
| `playwright` и `computer-use` | Playwright подходит для повторного прогона веб-панели. Управление Windows пригодится для проверки записи и просмотра ролика, если потребуется работа через интерфейс. |
| `spreadsheets:Spreadsheets`, `pdf:pdf`, `documents:documents` | Табличный навык применим после получения официального файла расчёта. PDF и Documents подходят для ручной сверки проблемных страниц и таблиц, если они есть в корпусе. |
| `skill-creator` | Для оформления подтверждённой повторяемой процедуры по отдельному решению. |
| `D:/myai` | В доступном обходе `SKILL.md` не обнаружены. Обнаружены отдельные учебные каталоги интенсива и курса ChatGPT/Codex, включая практику модуля 03, урока 03 с материалами и результатами. |

Перед фактическим применением навыка открыть его `SKILL.md` по каталогу текущей сессии. Для проектирования использованы уже доступные инструменты. Глобальные конфигурации навыков и проектные политики не менялись.

## Возможные проектные навыки

| Приоритет | Процедура | Когда извлекать |
| --- | --- | --- |
| Высокий | Приёмка RAG по версиям и доказательствам: эталонные локаторы, применимость, конфликты, безопасные отказы, отложенная выборка. | После повторного прогона на другом корпусе. |
| Высокий | Измерение локальной LLM на GPU и CPU: одинаковый набор запросов, параметры, холодный и тёплый режимы, телеметрия и расчёт запроса. | После двух воспроизводимых прогонов на разных конфигурациях или проектах. |
| Средний | Безопасный выпуск демо и репозитория: проверка истории, корпуса, условий доступа и доказательство внешней доступности. | После фактической сдачи и применения на следующем проекте. |
| Средний | Учебная проверка табличных артефактов: структура данных, формулы, открытие в целевом приложении, доказательства и ограничения. | Сопоставить фактические результаты нескольких учебных практик, затем извлечь общий порядок. |

Разовый сценарий этого ролика и правила конкретного кейса остаются в документации. Повторяемый навык оформлять в `.agents/skills/` после подтверждения входов, результата и границ применения.

## Независимая проверка

Инструмент списка субагентов ответил, в текущей команде активен только основной агент. Для предспринтовых проверок делегирование не потребовалось. После получения ТЗ независимому ревью полезно отдать корректность редакций на эталонах, возможное раскрытие данных в стенде и Git, повторяемость расчёта. Для такой проверки достаточно синтетики, обезличенных метрик и разрешённых материалов.
