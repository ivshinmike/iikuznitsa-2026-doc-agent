# Primelab Knowledge Agent

Веб-прототип для поиска ответов по корпоративным регламентам. Сотрудник задаёт вопрос обычным языком и получает выдержку с названием документа и номером пункта. Когда правила различаются по подразделениям, агент помогает выбрать нужное. Если подтверждения нет, вопрос передаётся в службу качества.

[Демонстрационный HTTPS-стенд](https://iikuznitsa.primelab-ai.com) · вход через браузер с учётными данными для просмотра.

Релизная версия приложения — `9e7d108eeedbe2d88b445c717607273ab4da2c0c`.

## Три конкурсных сценария

1. **Точный ответ.** Агент выбирает применимый пункт и показывает дословную выдержку с источником. При отсутствии подтверждения создаёт обращение.
2. **Уточняющий диалог.** Агент сохраняет исходный вопрос и запрашивает подразделение или недостающие условия, чтобы выбрать применимое правило.
3. **Пополнение базы знаний.** Сотрудник качества со своим доступом утверждает дополнительное знание и при необходимости одну альтернативную формулировку. После утверждения агент может использовать запись в пределах подразделения и актуальной редакции источника.

## Архитектура и модель

DOCX → извлечение нумерованных пунктов → SQLite FTS5 → поиск по подразделению → локальная Ollama → проверка цитаты → веб-ответ.

Приложение написано на Python 3.11, FastAPI и Uvicorn. Интерфейс использует HTML, CSS и JavaScript. На стенде работает Google Gemma 3 4B IT, тег Ollama `gemma3:4b`, квантование Q4_K_M. Браузер обращается к приложению по HTTPS через Caddy. Инференс, индекс и база знаний работают локально. В демонстрационном контуре письмо принимается локальным Mailpit.

## Локальный запуск

1. Установите Python 3.11 и Ollama. Запустите Ollama и загрузите модель `ollama pull gemma3:4b`.
2. В корне репозитория установите зависимости `python -m pip install -r requirements.txt`.
3. Создайте каталог `data` и поместите туда разрешённый DOCX. Для пробы подойдёт собственный документ с заголовком «1. Заявки» и пунктом «1.1. Координатор проверяет заявку после регистрации». Сохраните его как `example.docx`. Создайте рядом файл `corpus.json` в UTF-8.

```json
[
  {"file": "example.docx", "unit": "dbrct", "title": "Демонстрационный регламент"}
]
```

Поддерживаемые коды подразделений — `dbrct`, `security`, `technical`. Имена файлов в манифесте задаются относительно манифеста.

4. Постройте индекс и запустите веб-приложение из корня репозитория.

```powershell
python -m src.corpus data/corpus.json --db data/knowledge.sqlite
python -m uvicorn src.app:app --host localhost --port 8001
```

5. Откройте `http://localhost:8001`, выберите ДБРЦТ и спросите «Кто проверяет заявку после регистрации?».

Чтобы использовать панель качества, задайте в окружении процесса `IIKUZNITSA_QUALITY_KEY` случайным секретом, который хранится вне Git, и откройте `/quality` в локальном приложении. Имя для аудита берётся из `IIKUZNITSA_QUALITY_REVIEWER`. Для тестовой почты можно запустить Mailpit на том же компьютере и указать порт SMTP переменной `IIKUZNITSA_MAILPIT_SMTP_PORT`. Без этой настройки обращения сохраняются в локальной базе.

Автотесты запускаются командой `python -m unittest discover -s tests -v` после установки `requirements-dev.txt`. Для изоляции перед запуском задайте `IIKUZNITSA_DB` путём к отдельной тестовой базе.

## Контроль качества и ограничения

- Модель выбирает выдержки из найденных пунктов. Приложение проверяет, что каждая цитата существует в указанном пункте и относится к выбранному подразделению. Если подтверждения недостаточно, приложение сообщает об этом.
- Действующий регламент сохраняет силу. Предложение, которое расходится с правилом, остаётся на дополнительном согласовании. Интерфейс показывает действующий пункт и предупреждение.
- Доступ к утверждению отделён от доступа для просмотра. Непротиворечащее дополнение привязывается к источнику и его редакции. При смене редакции прежняя запись теряет применимость.
- Показан конкурсный прототип. Корпоративные интеграции, автоматическое применение исключений руководителя и произвольное сопоставление перефразировок вне утверждённой альтернативы не реализованы. Исходный корпус и индекс хранятся отдельно.
